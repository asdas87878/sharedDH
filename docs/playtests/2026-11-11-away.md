## Fixed bug

Both the meter warning and the final fade unconditionally said `OUT OF AIR!` on a missed hop, despite 99/100 Oxygen.
`HudController` and `DeathController` now read the existing server `DeathQuick` flag: `MISSED THE FISH!` for a missed
hop; `OUT OF AIR!` for actual depletion. The fresh playtest captured both fade messages in telemetry and showed the
corrected meter warning in a screenshot. The timing, physics and failure rules are unchanged.

Validation: `stylua --check src`; `selene src` (0 errors, 0 warnings, 0 parse errors);
`rojo build -o /tmp/ride-a-fish-away.rbxlx` passed. `git diff --check` passed.

## Logs and limitations

No game-script runtime errors were observed. Both starts logged an asset-type mismatch for `rbxassetid://203785492`
(not referenced in `src/`; origin not isolated). LaneSurvey reported one floor sample over 3 studs off and one missing.
Teleporting the mounted fish between zones triggered the expected `fish moved too fast` warning; that is a test artifact.
The runner's own initial inspection mistakes were corrected and are not game-code failures.

No person judged steering, mouse/free-camera comfort, gamepad/mobile aiming, target choice at the exact range boundary,
two-player contention or network lag. Only the three lands in the current place were exercised. Existing observations
about floor tiles being breakable props and the HUD showing wanted speed against a wall remain outside this small fix.
