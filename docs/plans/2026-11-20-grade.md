## Numbered issues

Severity: **High** blocks a requested usable behavior or explicit review gate; **Medium** is a correctness/acceptance gap requiring a fix or proof; **Low** is documentation or inherited tooling debt. Source-based findings are identified as such; no unseen runtime reproduction is implied.

1. **Medium — E1: the main Oxygen stat still abbreviates.** `src/client/UI/StatRows.luau:271` calls `Kit.short(whole)`, so training to 2,925 still displays an abbreviated decimal K value. Tags, needs text and trainer pops were migrated, but this stat was missed. **Fix:** use `Config.wholeNumber` for this oxygen row, size it for large values, and check 2,925 and 3,285,000 on desktop/phone. Keep coin formatting independent.

2. **High — E1: elapsed time is not settled at event boundaries.** `src/server/Services/TrainService.luau:764` increments the level and clears `Carry`, without accounting for time since the previous polling tick; `:841`/`:855` subsequently grant the full global polling `dt` at the new level. Example: old carry 0.95 s, upgrade 0.07 s after the last poll loses a completed old-level second; the next poll also counts some pre-upgrade time toward the new level. `:658` similarly discards unaccounted elapsed time at dismount. Legacy pad `:581` awards the entire polling interval on first detection, even if the player just arrived. **Fix:** maintain an eligible-time timestamp per rider; settle completed old-level ticks at upgrade/dismount/death, discard only the fractional remainder, reset timestamp at new-level start/entry, and never charge an interval before eligibility. Test events between polls and delayed updates, including legacy entry/exit. The pure `trainTicks` test does not exercise this.

3. **Medium — E1: existing tanks retain stale earnings after live tuning.** `src/server/Services/SandboxService.luau:29` updates oxygen multipliers and calls `Config.refresh()`, while `src/server/Services/AquariumService.luau:920` pays cached `tank.Income`. Recount at `:451` only runs during tank mutations (`:499`, `:511`, `:542`). Meanwhile the client computes new card incomes from Config. **Fix:** notify AquariumService on relevant config refresh; recount/resort each existing tank and republish attributes before subsequent payouts. Verify a stocked tank after changing size/rarity/variant oxygen or PerRequired, without depositing another fish.

4. **High — E3: Q slot/hint is off-screen on narrow phones.** `src/client/UI/Slots.luau:372` puts Q outside the centred seven-slot frame; `:536` uses fixed 34 px touch tiles/8 px gaps without viewport fit. At scale 1 the numbered row is 286 px, and Q's left edge is `viewportWidth/2 − 193`: −5.5 px at width 375 and −33 px at width 320, before the outline/hint. `src/client/Controllers/HudController.luau:222` scales by height only, making portrait-phone overflow worse. **Fix:** preserve the inventory row's original centre while fitting the entire Q-plus-row extent within safe bounds; use a deliberate compact phone arrangement if necessary. Check actual touch equip, mount and X at 320/375-wide viewports, with HUD overlap and practical target sizes.

5. **Medium — E3: debug number capture is not exclusive.** `src/client/Controllers/EquipController.luau:104` only checks processed/text focus. `src/client/Controllers/FeelLogController.luau:543` independently consumes numbers while `pickUntil > 0`, a six-second window that is not cleared merely by returning Dock (`:507`). Mark a dive, return to Dock before expiry, then press a number: it can both answer FeelLog and hold inventory. **Fix:** expose an input-capture flag or central priority routing; suppress hotbar keys during debug/modal capture. Exercise the real InputBegan path and chat/search focus, not just `press()`.
